### Outcomes

[07:20] Brainstorming complete — 3-layer orchestration model agreed:
  - Layer 1: Opus (Jarvis) — passive orchestrator, communication gate with human
  - Layer 2a: Sonnet Team Leads — per-area autonomous coordinators, commit gate
  - Layer 2b: Sonnet PM — cron-based heartbeat controller, pushes stalled TLs
  - Layer 3: Sonnet/Codex workers — development/analysis/review

Key decisions:
  - D1: Token optimization is PRIMARY design constraint
  - D2: Opus is passive — never polls, never monitors
  - D3: PM is cron-based scheduled trigger, not long-running session
  - D4: PM escalates to Opus only after 2x failed push
  - D5: TL persists state to file for context exhaustion resilience
  - D6: PM handles dynamic TL list (replacements possible)
  - D7: Every branch has ≥1 Sonnet for commit gate
