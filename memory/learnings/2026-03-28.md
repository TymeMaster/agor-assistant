# Learnings: 2026-03-28

## Workflow Process Observations (WB — Areas → WB — Tasks)

### Issue: Codex agents cannot commit (sandbox restriction)
- Codex sessions run in a sandbox without git write access
- Work breakdown review docs were left uncommitted for 4 days
- **Action:** Standardize that commits are always done by Claude Code sessions or the orchestrator
- **Workflow doc update needed:** Note in AI_WORKFLOW docs that commit gates require git-capable agent

### Issue: No explicit commit gate between workflow phases
- Workflow mentions "[User Approval and git commit]" but doesn't specify who/when
- **Action:** Add checklist to each phase: "Before next phase: ☐ Outputs committed ☐ Branch pushed"

### Issue: Orchestrator manually assembles context prompts
- Had to read workflow docs, find context file list, manually compose agent prompt
- Works but error-prone and repetitive
- **Action:** Consider zone trigger templates or per-task CONTEXT.md files

### Issue: No "owner session" tracking for worktrees
- Had to scan all 8 sessions to find the right one to prompt for commit
- **Action:** Use worktree notes/metadata to track primary working session ID

### Issue: File permissions differ between Codex and Claude Code
- Codex creates files as -rw-r--r--, Claude Code as -rw-r-----
- Minor but visible in `ls -la` output

### What worked well
- Workflow documentation (ANALYST.md, REVIEWER.md) is clear and complete
- Agent produced high-quality Area 1 task breakdown in single pass (~110s)
- Context Loading table in workflow docs maps exactly to what agent needs
- Multi-agent handoff (analyst → reviewer → analyst revision) produced good review cycle
