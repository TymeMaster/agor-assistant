# Learnings: 2026-03-29

## Subsession Spawning Works Well

**What worked:**
- Both Codex and Claude Code subsessions spawned successfully
- Callback mechanism worked reliably (notified on completion)
- Both delivered high-quality analytical output without tool use
- Stats visible: message count, completion status

**Key insight:** Subsessions are excellent for parallel analytical work (process review, consistency checking, research) without cluttering orchestrator context.

## Model Override Is Not Supported

**Discovery:** Agor MCP does NOT support model override when spawning or creating sessions.

**What we tried:**
1. `extraInstructions` with model preference → ignored
2. Checking session metadata for `model` field → doesn't exist
3. Looking for user preferences with model config → not available
4. Searching Swagger docs → not accessible via localhost

**Root cause:**
- `agor_sessions_spawn` and `agor_sessions_create` only have `agenticTool` parameter
- Model is determined by `agenticTool` choice, not configurable
- `claude-code` → always Sonnet 4.5
- `codex` → always Codex

**Workaround:**
- For Opus sessions (Architect role), create manually in GUI
- Accept Sonnet default for Claude Code agent
- Use Codex for analytical/review work

**Lesson:** Don't promise model override to user. Document the limitation and work within constraints.

## Commit Gate Strategy Clarified

**Problem:** Codex sandbox cannot perform git operations (commit, push).

**Old approach risk:** Developer sessions (Sonnet or Codex) handle implementation AND commit → workflow deadlock if Codex can't commit.

**New strategy:**
1. Worker sessions (Developer/Reviewer) **produce code only**
2. Board assistant or its subsession **handles all commits**
3. Keep commit-capable sessions (claude-code) on critical path for closure
4. Never delegate final commit to Codex sessions

**Why this matters:**
- Avoids "review approved but can't commit" deadlock
- Centralizes git operations with proper permissions
- Simplifies workflow: workers work, orchestrator commits

**How to apply:**
- After worker session completes: orchestrator reviews changes → commits → pushes
- Document in workflow: "commit gate is orchestrator responsibility"
- Don't spawn commit tasks to non-commit-capable agents

## Process Weaknesses From Codex Analysis

Codex identified these patterns from feat-walls development:

1. **Orchestration reliability** - Agor prompt operations can fail, need fallback playbook
2. **Session observability** - Need health checks post-spawn (verify messages/activity)
3. **Worktree hygiene** - Dirty files accumulate, need cleanliness gates between areas
4. **Agent capability split** - Codex can't commit, architect workflow accordingly
5. **Multi-role overhead** - Full analyst→developer→reviewer too heavy for small tasks

**Actionable:**
- Add health checks after spawn (30-60s timeout)
- Document orchestration failure fallback
- Enforce worktree cleanliness before next area
- Scale workflow complexity to task size
